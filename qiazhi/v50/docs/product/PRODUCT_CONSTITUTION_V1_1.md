# DeepLife Product Constitution v1.1

## Principle 0: Mingli First

DeepLife 首先是以 DeepBazi 专业命理认知为内核的智能命理系统。Life OS 是命理认知在时间、现实反馈与长期案例中的延伸，不是泛化人生教练。

任何正式展示、保存或用于后续推理的洞察，都必须有可追溯的命理依据。依据不足时，系统保留不确定性或拒绝形成判断，不使用通用心理话术填补空白。

发生冲突时，优先级固定为：

```text
专业命理依据
> 个性化体验
> 叙事趣味
> 用户活跃度
> 对话流畅度
```

## 产品分工

```text
DeepBazi：形成专业命理认知
DeepLife：维护长期生命案例
Abu：让用户自然地理解、探索和操作这个案例
```

## 首次体验

```text
欢迎与建档
→ 确定性排盘并确认命盘
→ 一次核心 LLM 形成整盘基线
→ Draft Preview
→ 事实、引用与版本检查
→ 提交 Life Case v1
→ 展示当前确定性时间状态
→ 用户主动选择专题
→ 按需执行专题 Reasoner
```

首次基线只回答：整盘重心、主要运行路径、增强或受阻条件、竞争假设与不确定性。它不提前生成所有人生领域。

## 硬性边界

1. 首次用户阻塞的强模型调用不超过一次。
2. 命盘事实在 LLM 返回前可查看。
3. Draft Preview 不写入 Life Case。
4. 正式洞察必须通过引用、命盘版本、必要字段与不确定性检查。
5. 未选择的人生领域不预计算。
6. 现实反馈只更新当前案例，不修改命盘事实或全局理论。
7. Temporal Prior 与事后 Case Revision 分开保存。
8. 页面展示当前案例状态，Abu 负责解释、导航与受控操作。
9. 页面按钮和 Abu 使用同一个 Action Registry。
10. 健康输出不诊断、不指导停药或换药。

## 当前阶段不做

```text
Daily 推送
生命小剧场
大规模领域页面
泛化陪伴对话
事后覆盖先验
```

这些能力必须建立在 Life Case、Formal Insight、Baseline Reasoner 和提交协议之上。
