# V50 人生领域系统

领域不是页面栏目，也不是十二份模板。它们是同一份整盘认知在不同人生问题上的推理任务。

## 完整领域空间

```text
整盘命局
自我与性情
天赋与学习
事业与职业
财富与资源
亲密关系
家庭与原生关系
子女与传承
健康与生命力
社交与合作
迁移与环境
人生阶段与时机
```

## 成熟度与可探索性

- `live`：已有较完整的领域协议，可以形成较深的条件性推演；
- `partial`：已有足够事实和工具，可以探索，但必须保留更多未知项；
- `research`：允许进行受边界约束的探索，用于形成可证伪的案例假设，不能把研究假设包装成确定结论。

成熟度不是“能不能点开”的开关，而是推理深度、语言强度和验证要求。完整领域都可以进入；任何专题如果没有通过事实、证据、反证和安全边界审阅，就直接失败，不用模板补位。

## 专题推理协议

除整盘外，每个领域都必须定义：

```text
核心问题
领域因果焦点
相关紫微宫位
Probe 的区分目标
禁止断言
公开深度
```

一次专题推理必须从已冻结的整盘认知出发，形成恰好四步的案例因果链，并至少提出两条可证伪断言。它可以引用八字、紫微与时序事实，但不能改写整盘主假设、主做功、用神逻辑或命盘事实。

```text
整盘认知
→ 用户当前人生问题
→ 领域 Context
→ LLM 专题推理
→ 领域断言与反证
→ 领域级 Probe
→ 案例断言更新
```

领域 Probe 只更新当前案例的领域断言，不自动修改整盘主假设，更不能修改全局理论。

## Abu 的处理原则

1. 理解用户的真实问题，而不是要求用户先选菜单；
2. 把问题映射到领域与具体 Intent；
3. 检查该领域所需事实、知识、时序和现实上下文；
4. 按领域成熟度编译不同深度的上下文并进入推理；
5. 直接显示该领域的成立条件、失效条件、未知项和公开边界；
6. 每次只提出一个真正有信息增益的问题；
7. 绝不把一个领域偷偷映射成事业或财富，也不为每个领域套一份固定栏目文案。

## 角色深度

- 游客：一个识别点、核心因果链、一个机会条件、一个风险条件和一个 Probe；
- 会员：完整领域理解、条件、方向、未知项和案例级 Probe；
- 命理师：完整断言、支持与反证、审阅结果和专业问题；
- 研究者：额外看到领域协议、验证问题和可贡献的反例入口。

四种角色读取同一份 `DomainExploration`，不会触发四套命理判断。

领域注册表的可执行定义位于 `packages/core/life_domains.py`。
