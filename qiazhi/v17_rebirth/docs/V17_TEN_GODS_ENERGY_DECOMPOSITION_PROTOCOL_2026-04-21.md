# V17 十神能量分解协议

## 1. 目标

V17 的十神分值不再被视为“一个来源不明的单一分数”。

从 2026-04-21 起，系统设计正式切换到四段式解释口径：

- `manifest_energy`
- `root_energy`
- `momentum_energy`
- `hidden_residual`

这不是四套互相独立的最终结果，而是同一十神强度的四个来源层。

---

## 2. 为什么要拆

如果只保留一个总分，会反复混淆以下概念：

- 天干是否明透
- 地支是否真正通根
- 禄、临官、帝旺、羊刃是否只是“势强”
- 只有藏干、没有透干时是否只是“潜藏残值”

例如：

- `丙见巳`
  - 对丙火来说，巳藏丙，属于本根更纯
- `丙见午`
  - 对丙火来说，午为帝旺、羊刃，属于势更猛

两者都强，但强法不同，不能用一个“火分数”糊成一团。

---

## 3. 四段定义

### 3.1 `manifest_energy`

定义：

- 十神直接在天干明透所形成的显化能量

特点：

- 最接近“这个十神已经上台”
- 是后续根气、势能放大的主通道
- 原局天干显化还受“贴身显化权重”影响，原则上 `月干 > 时干 > 年干`
- `贴身显化` 只描述天干离日主有多近、做功有多直接，不属于根气
- 日干本身是十神参照轴，不直接计入 `manifest_energy`

例：

- 丙日主见丙，为比肩的 `manifest`
- 丙日主见壬，为七杀的 `manifest`

### 3.2 `root_energy`

定义：

- 地支对已显化十神的根气支撑

根气分级：

- `本根`
  - 同五行、同阴阳、同字根
- `异阴阳根`
  - 同五行，但阴阳不纯配，需折损
- `潜藏根`
  - 仅有藏干，未透出，只保留弱支撑

原则：

- 先看五行是否可通根
- 再看阴阳是否纯配
- 本根强于异阴阳根
- 异阴阳根强于纯潜藏残值

### 3.3 `momentum_energy`

定义：

- 不直接等于“根”，而是禄、临官、帝旺、羊刃、月令场势等带来的位置性增益

原则：

- `momentum` 只能增强已有通道，不能凭空制造一个强十神
- 没有显化、也没有根，只靠势能不能把十神炸出来

典型例子：

- `巳` 更偏根
- `午` 更偏势

从 2026-04-21 起，`momentum_energy` 在实现层进一步拆为四个可审计细项：

- `momentum_month_order`
  - 月令只作用月支自身时产生的场势增益
- `momentum_stage`
  - 十二长生阶段势，专门记录长生、临官、帝旺等位势带来的增益
  - 其下再拆为：
    - `momentum_stage_lu`：临官/建禄类位势
    - `momentum_stage_blade`：帝旺/羊刃类位势
    - `momentum_stage_general`：长生、冠带、墓、胎、养等一般阶段势
- `momentum_structure`
  - 三合、结构回灌、成局投影等结构性势能
- `momentum_auxiliary`
  - 性别微调、轻辅助偏置等非结构型小增益
- `momentum_other`
  - 预留桶，承接未来尚未独立建模的势能来源

### 3.4 `hidden_residual`

定义：

- 只有藏干存在、没有明透、也没有形成强根时，保留的小残值

作用：

- 表示“盘中有苗头”
- 但不能视为已经显化成主轴

## 4. 合成规则

### 4.1 禁止的旧口径

禁止再使用：

```text
总分 = 所有同元素来源直接累加
```

这会导致：

- 月令广播污染
- 纯藏干虚浮被算成强轴
- 羊刃与本根混淆

### 4.2 新口径

推荐合成公式：

```text
entity_energy = manifest_energy + root_energy
total_energy = entity_energy * (1 + momentum_ratio) + hidden_residual
```

说明：

- `manifest + root` 代表“这个十神实体上是否站住”
- `momentum_ratio` 代表“是否得势、是否有舞台”
- `hidden_residual` 只作为尾部残值，不参与大规模放大

如果当前阶段尚未正式产出 `momentum_ratio` 结构体，则允许过渡态：

```text
total_energy = manifest_energy + root_energy + momentum_energy + hidden_residual
```

但 UI 与 LLM 必须明确知道它们是四个不同来源。

---

## 5. 当前 L0 过渡映射

在现有实现中：

- 天干明透贡献，逐步映射到 `manifest_energy`
- 通根、本根、异阴阳根，逐步映射到 `root_energy`
- 月令、禄刃、长生十二运相关位置势，后续逐步映射到 `momentum_energy`
- 未透藏干折损，映射到 `hidden_residual`

当前代码还处于“L0 先校口径、结构逐步显式化”的过渡期，因此：

- 算法上已经开始按这套理念收口
- 数据结构上下一步再正式拆字段

---

## 6. LLM 提示词解释合同

所有 narrator / judge / reasoning 相关 prompt，必须明确收到以下解释：

1. `ten_gods_base_l0` 不是比例值，而是绝对物理强度。
2. 单个十神总分并非单一来源，而是由显化、根气、势能、潜藏残值共同组成。
3. `根气` 与 `势能` 不是一个概念。
4. `巳` 对丙火偏“根”，`午` 对丙火偏“势”。
5. 只有藏干、未透干时，通常只能视为弱支撑，不可直接等同强轴。

## 7. UI 展示建议

每个十神建议最终展示为：

```json
{
  "比肩": {
    "total": 28.4,
    "manifest": 10.0,
    "root": 9.2,
    "momentum_ratio": 0.72,
    "hidden": 1.8
  }
}
```

UI 主视图：

- 显示 `total`

展开层：

- 明透
- 根气
- 势能
  - 月令势
  - 阶段势
    - 禄势
    - 刃势
    - 长生势
  - 结构势
  - 辅助势
  - 其他势
- 潜藏

## 8. 下一步落地

1. 在 `ten_gods_engine.py` 中把四段字段显式写入 `meta`
2. 在 `PhysicsCanonicalService` 中把解释合同下发给 LLM
3. 在 `SixPillars / TracePanel / Admin Core Engine` 中把分解账本展示出来
4. 把禄、临官、帝旺、羊刃正式并入 `momentum_energy`
5. 继续将 `momentum_other` 逐步消解为可命名的势能来源，避免黑箱桶长期存在

---

## 9. 结论

V17 的十神不再只是“一个分数”。

它必须同时回答四个问题：

- 有没有明透
- 有没有根
- 有没有势
- 只是潜藏，还是已经成轴

只有这样，系统才会真正接近命理师的判断路径。
