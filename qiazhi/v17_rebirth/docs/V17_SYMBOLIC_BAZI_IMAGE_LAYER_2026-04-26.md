## 1. 核心判断

当前财富、事业、感情、性格等宏观主题，已经能从十神、体用、格局、盲派、象法、调候、关系动力等材料中提取主题强弱和风险。但这还不够。

十神回答的是“谁和日主发生关系”，却不能完整回答“这个关系长什么样”。同样是财星，甲木财、乙木财、丙火财、壬水财在现实世界里的财富象完全不同。

因此 V17 需要一个更底层的 L0 象义插件：

```text
v17.symbolic.bazi_image.v1
```

它只负责把八字中的天干、地支、阴阳五行、十神、宫位、藏透、合冲刑害等材料转成结构化象义事实，不做吉凶断语，不预测事件，不修改任何参数。

一句话原则：

```text
十神是角色，天干是材质，地支是场景，宫位是人生领域，岁运是触发器。
```

## 2. 层级定位

`v17.symbolic.bazi_image.v1` 属于 L0 象义事实层。

它读取：

- 原局四柱。
- 天干地支。
- 阴阳五行。
- 十神映射。
- 藏干与透干。
- 宫位位置。
- 基础合冲刑害。
- 已有 L0/L1 的能量与关系事实。

它输出：

- 干支象义。
- 十神角色象义。
- 宫位场景象义。
- 藏透状态。
- 象义组合事实。
- 可供 L3 专题插件消费的证据。

它禁止：

- 不裁决体用。
- 不改强弱参数。
- 不生成“必发财”“必离婚”等断语。
- 不直接给普通用户暴露专业术语。
- 不让 LLM 自由读取原始八字后重新解释。

## 3. 天干象义原型

第一版采用“象义原型 + 领域投影”的方式。天干不直接等于行业或事件，而是提供材质、形态和变现风格。

| 天干 | 基础象 | 财富投影 | 事业投影 | 风险投影 |
|---|---|---|---|---|
| 甲 | 大树、梁柱、向上生长、组织骨架 | 大项目、长期资产、组织资源、成长型业务 | 负责框架、管理骨干、长期建设 | 过直、周期长、转身慢 |
| 乙 | 花草、藤蔓、柔性连接、审美细节 | 细分服务、审美产品、关系型复购 | 协调、设计、内容、服务 | 依附性、边界弱、易受环境影响 |
| 丙 | 太阳、曝光、公开、热度 | 品牌、流量、传播、公开市场 | 表达、影响力、舞台、领导曝光 | 过热、消耗快、声量大于沉淀 |
| 丁 | 灯火、技术、洞察、精细判断 | 咨询、技术、手艺、精密服务 | 策略、研究、专业判断 | 过度敏感、能量不稳、需要载体 |
| 戊 | 高山、平台、承载、边界 | 平台、地产、重资产、稳定承载 | 组织平台、资源承接、基础设施 | 固化、迟钝、压住流通 |
| 己 | 田园、培育、运营、系统维护 | 运营、库存、供应链、服务系统 | 管理细节、流程、照料、经营 | 琐碎、内耗、泥沙混杂 |
| 庚 | 矿石、机器、工具、规则、执行 | 硬资产、工具化产品、制造、执行收益 | 执行、工程、制度、攻坚 | 刚硬、冲突、成本高 |
| 辛 | 珠玉、精密、审美溢价、凭证 | 金融凭证、品牌质感、精密产品 | 品控、审美、法务、金融、精修 | 挑剔、脆弱、过度包装 |
| 壬 | 江河、流通、远方、信息流 | 贸易、流通、跨境、资金流、信息差 | 资源调度、市场、迁移、传播网络 | 漂移、失控、现金流波动 |
| 癸 | 雨露、数据、隐性需求、微循环 | 数据、研究、小额持续现金流、订阅 | 研究、分析、隐性服务、润物细无声 | 隐蔽、迟缓、方向感弱 |

## 4. 地支象义原型

地支不是生肖标签，而是“场景、根气、库位、运动状态”的集合。

第一版地支输出至少包含：

- `season_context`：季节环境。
- `root_context`：根气与藏干。
- `storage_context`：是否具备库、墓、蓄水、沉淀属性。
- `movement_context`：合冲刑害带来的运动、开合、阻滞。
- `palace_context`：出现在年、月、日、时柱时代表的人生场域。

示例：

```json
{
  "branch": "辰",
  "image_tags": ["湿土", "水库", "混合资源", "蓄藏"],
  "storage_context": {
    "has_vault_signal": true,
    "vault_material": ["水", "土", "木余气"],
    "default_state": "stored_not_released"
  },
  "movement_context": {
    "needs_trigger": ["冲", "刑", "合化", "岁运引动"],
    "risk": ["开库不等于进财，也可能是资金流动或资产转换"]
  }
}
```

## 5. 十神角色与天干材质的组合

十神只提供角色，天干提供材质。二者组合后才进入主题插件。

例如同样是财星：

| 财星材质 | 内部象义 | 用户财富语言 |
|---|---|---|
| 财为甲 | 财源像长期生长的大项目 | 钱更容易来自长期项目、组织资源、成长型业务 |
| 财为乙 | 财源像柔性服务和审美连接 | 钱更容易来自服务、审美、关系复购、细分市场 |
| 财为丙 | 财源像曝光和公开市场 | 钱更容易来自品牌、传播、流量、公众影响力 |
| 财为丁 | 财源像精密技术和洞察 | 钱更容易来自咨询、技术、手艺、专业判断 |
| 财为戊 | 财源像平台和重资产 | 钱更容易来自平台、地产、库存、稳定承载 |
| 财为己 | 财源像运营和供应链 | 钱更容易来自运营、服务系统、供应链、复购经营 |
| 财为庚 | 财源像工具和硬执行 | 钱更容易来自工具、工程、设备、规则化交付 |
| 财为辛 | 财源像精修和溢价 | 钱更容易来自品牌质感、精密产品、金融凭证 |
| 财为壬 | 财源像流通和交易 | 钱更容易来自贸易、资金流、跨区域资源、信息差 |
| 财为癸 | 财源像数据和隐性需求 | 钱更容易来自研究、数据、小额持续现金流、隐性服务 |

## 7. 与财富插件的关系

`wealth_profile` 仍保留为主题摘要层。

新的财富密码插件 `wealth_code` 应消费 `bazi_image`，从中读取：

- 财星是什么材质。
- 财星透藏在哪里。
- 财星在哪个宫位。
- 谁在引动财星。
- 财库是否存在，以及库的材质和状态。
- 食伤、官杀、印、比劫分别是什么材质。

这样财富判断才会从“财富机会较明显”升级为：

```text
这类钱更像长期项目还是流量机会？
靠技术、表达、平台、资源整合，还是资产沉淀？
钱容易进入现金流，还是沉在库存、资产、项目回款里？
```

## 8. 知识库形态

建议使用版本化知识库：

```text
v17.knowledge.bazi_symbolic_primitives.v1
```

每条规则包含：

```json
{
  "id": "stem.jia.wood.v1",
  "symbol": "甲",
  "classic_terms": ["阳木", "参天大树"],
  "image_tags": ["大树", "梁柱", "长期生长", "组织骨架"],
  "domain_projection": {
    "wealth": ["长期项目", "成长型业务", "组织资源"],
    "career": ["管理骨干", "框架建设"],
    "risk": ["周期长", "过直", "转身慢"]
  },
  "school_notes": [],
  "source_type": "curated_rule",
  "confidence": 0.75
}
```

知识库可以持续扩展，但发布必须走治理：

- 规则新增先进入 draft。
- 命理师审核后进入 candidate。
- 合成样盘和真实样盘验证后进入 stable。
- 派别差异必须保留 `school_notes`，不能强行合并。

## 9. 验收标准

第一版验收：

- 可以为任意八字输出干支、十神、宫位、藏透的象义事实。
- 不输出吉凶断语。
- 不修改任何现有参数、体用裁决或格局候选。
- 财富插件可以读取财星材质、财库材质、变现器材质。
- UI 默认不暴露该层，只作为后台审计和专题插件输入。

长期验收：

- 命理师能在后台看到象义证据链。
- 专题插件能引用象义事实解释财富、事业、感情、性格差异。
- LLM 只能消费结构化象义合同，不能自由回读原始八字。
