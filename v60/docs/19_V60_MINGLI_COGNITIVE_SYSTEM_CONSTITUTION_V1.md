# 阿布知命命理认知系统宪法 v1

状态：`OWNER_APPROVED_AND_IMPLEMENTATION_ACTIVE`

日期：2026-08-02

适用范围：V60 命理测算、Lab、阿布说、阿布梦境、八字剧场、题库、知识库、
规则库、518K／命运奇点研究、合成命盘验证与 LifeCase。

## 1. 产品命题

阿布知命的核心不是一个套模板的报告生成器，也不是一个换皮聊天窗口。

正式产品是：

> **由可复核命盘事实、专业知识与规则、竞争解释、时间推演、现实观察和持续验证
> 共同约束的命理认知系统；对外由一个连续的命理师人格——阿布——提供判断、
> 解释、追问与演出。**

通用 LLM 可以写一篇听起来像算命的文章，但它不天然拥有：

- 本产品唯一、版本化且可恢复的 Case／Chart／Reading；
- 同一判断在命理枝、Lab、阿布说、Dream 和剧场中的一致引用；
- 事实、解释、应事、应期和用户反馈之间不可混淆的边界；
- 合成单变量对照、反证、稳定性复测和长期 LifeCase；
- 每次判断采用了什么知识、规则、Prompt、模型和证据的谱系；
- 一次推演、多处复用、刷新不重算的产品成本与体验控制。

这些能力构成阿布知命相对于“直接问 ChatGPT”的意义。

## 2. 三个中心

### 2.1 Reading Claim Graph：认知中心

正式 Reading 不是一篇不可拆解的文章。它必须投影为同一张 Claim Graph。

每个 Claim 至少包含：

- `claim_ref`、层级与类型；
- 判断正文及成立条件；
- 因果链与证据引用；
- 置信度和适用时间范围；
- 竞争解释、支持或时间引动关系；
- 推理模式、模型／Prompt／知识／规则谱系；
- 专业审阅和现实校准状态。

整盘初断是必答对象，不再存在“所有解释项一起通过／一起失败”的总闸门。Claim 使用：

- `ESTABLISHED`：事实或已完成专业裁决的结论；
- `PROVISIONAL`：命理师已经给出的当前初断；
- `NEEDS_RECONCILIATION`：初断继续展示，但需要现实观察或专业复核区分；
- `WITHHELD`：只隔离这一条存在事实、时间层或作用越界的结论；
- `OPEN_QUESTION`：用于区分竞争解释的问题。

一个 Claim 被隔离，不能抹掉日主判断、整盘主线和其他可用 Claim。只有模型结果在结构上
无法读取，或改写 canonical 四柱、十神、坐标和准入关系时，当前生成才允许失败；产品仍须
保留上一份不可变 Reading 和安全重试入口，不能回退到模板或工程话术。

Claim 隔离必须具有依赖语义：`WITHHELD` Claim 不得继续通过 `SUPPORTS`、
`PROJECTS_TO` 或时间扩展边支撑其他结论；若整盘总纲的一条骨架依赖被撤下，总纲仍可作为
当前最佳初断展示，但必须降为 `NEEDS_RECONCILIATION`，不能伪装成普通已准入判断。条件字段
也不能替另一段无条件作用断言“洗白”。

命理测算、Lab、阿布说、Dream、剧场和题库只能引用同一 `claim_ref`，不得复制后
各自重新断命，也不得形成第二套真相。

### 2.2 Life Thread：体验中心

Life Thread 维持“这是同一个人在连续经历同一次命运探索”。它绑定当前档案叶、
Case、Reading、时间层、关注主题、问题、观察事件、场景状态和恢复游标。

跨模块跳转传递对象引用，不依赖无限增长的聊天记录，也不把页面局部状态冒充用户
长期画像。

### 2.3 阿布：唯一公开人格

对用户只存在一个连续的命理师人格。阿布可以在任意场景讲述、总结、追问、导演
字幕与角色演出，但不得脱离当前 Claim Graph 另造命理结论。

多多和 NPC 可以陪伴、反驳、提问和表演；专业命理裁决仍只能来自当前正式
Reading。

## 3. 四个平面

| 平面 | 权威内容 | 允许的主要写入者 |
|---|---|---|
| 事实平面 | Case、Chart、四柱、十神、藏干、排运、时间坐标、准入关系 | canonical 计算与准入服务 |
| 认知平面 | 专业卷宗、竞争解释、Claim Graph、资格评测、反证与研究批注 | Mingli Agent、Lab 审阅流程 |
| 实践平面 | 当前正式 Reading、Concern Thread、追问、Observation Ledger | 命理师流程与唯一 Admission |
| 体验平面 | 命理枝、六柱舞台、字幕、TTS、Dream、剧场、角色与恢复状态 | Projection／Scene／Narration |

上层可以引用下层，不能反向改写下层。一次 Dream 选择不是命盘事实，一段剧场剧情
不是现实应事，一条 LLM 解释也不能改写四柱。

## 4. 命理师 Agent 的正式职责

命理测算核心采用一个专职 Mingli Agent，而不是多个模型投票，也不是任意聊天。

它必须完成：

1. 锁定日主、月令、透藏、根位与支持角色；
2. 结合季节、位置、根气、生扶、泄耗克制与承载判断日主状态；
3. 建立真正竞争的整盘假设，并说明主解释为何胜出及何时失效；
4. 检查格局成败、救应、调候、扶抑、制化、通关和做功条件；
5. 写出从源端、转化到目标的主路径及闭合程度；
6. 由同一主解释推演理法、象法、人生应事和岁运应期；
7. 主动暴露区分竞争解释所需的关键问题；
8. 输出结构化判断，再由系统确定性生成 Claim Graph；
9. 保留模型、Prompt、卷宗、知识、规则和结果身份，支持复测与替换。

它不得：

- 重算或改写 canonical 命盘事实；
- 把关系成员坐标直接升级为关系已经起作用；
- 用用户经历反向编造盲断依据；
- 把模板栏目填满当作整盘判断；
- 把多 Agent 一致、用户喜欢或合成数据自洽冒充专业正确；
- 在 GET、刷新、切层、播放时再次调用模型；
- 以“当前模型可用”为由绑定产品架构。

## 5. 两种正式推理模式

### 5.1 `BLIND_READING`

盲断只允许读取命盘事实、时间坐标、准入知识与规则、专业卷宗和明确的研究候选。
姓名、性别刻板推断、真实经历、画像标签、Dream 选择、历史问答和旧断语均不得进入
模型 Prompt。

它回答：“只看这张盘，专业上能推到哪里？”

第一阶段所有对外候选 Reading 必须先通过盲断资格。当前已实现的整盘 Agent Prompt
实质上是盲断视图，本轮将把该边界升级为显式可验证合同。

### 5.2 `RECONCILIATION`

校准断在一个已冻结的盲断 Reading 之后，读取经过来源标注的 Observation Ledger，
用于：

- 验证或削弱竞争解释；
- 区分相近机制；
- 校正应事表达与时间窗口；
- 产生新 revision，而不是回写旧 Reading。

校准断不得把已知经历伪装成盲断命中。Observation Ledger 和准入流程尚未完成前，
该模式只保留合同，不允许生成或发布。

## 6. 模型政策

Mingli Agent Host 必须保持 provider／model 可替换。模型只是推理器官，不是产品
正本。

Owner 已确认，既有产品模型方向是 `gemma4:latest`；Qwen 在既有合同中属于
Research／Teacher 对照。上一轮整盘 Agent 错误地把 Qwen 试验配置延续为默认候选，
本轮纠正为：

- `gemma4:latest` 恢复为整盘 Agent 的首个产品资格候选；
- Qwen 输出保留为不可变对照证据，不再占据产品默认；
- Gemma4 仍须通过同一事实、内容和稳定性资格赛，不能因历史偏好直接发布；
- 当前 Gemma4 结果只允许进入私密 `OWNER_REVIEW_REQUIRED` 初断，
  `publication_allowed=false`；不具备公开专业资格不等于拒绝完成整盘判断；
- 模型替换不得改变 Case、Reading、Claim Graph 和 Experience Projection 合同。

Qwen3-TTS 是独立的声音引擎，不等于命理推理模型。

### 6.1 研发教师与方法蒸馏治理

前沿模型可以担任版本锁定的研发教师；当前 Codex/Sol 审读属于该研发平面，不属于
产品 Runtime。教师输出只能作为差异、错误、遗漏判法和反例的研究证据，不能自动写入
Reading、Knowledge、Rule、Prompt 或 Gold Reading。

正式治理链为：教师模型给出对照证据，Codex 提炼候选方法卡／规则／Prompt／Schema／
测试，Owner／专业复核决定是否准入，本地产品候选再通过合成反事实和稳定性资格赛。
这是一种系统方法蒸馏，必要时未来可以扩展到权重训练，但权重训练不是当前前提。

每次教师研究必须锁定并缓存模型精确版本、Case Packet Hash、Prompt／Schema 版本、
参数、输入输出 token、耗时和成本。前沿 API 只用于建立基线和里程碑盲检，不进入普通
用户一次主推理路径。`gemma4:latest` 仍是当前本地产品资格候选；Qwen3.8 只是未来
候选，必须通过同一合同和资格流程，不能因价格或 token 方案直接获得产品地位。

## 8. 一次生成，多处复用

正式链路为：

```text
Case / Chart / TimeContext
        ↓
专业卷宗（紧凑、可复核、只读）
        ↓
一次 Mingli Agent 推演
        ↓
不可变 Agent Reading
        ↓
确定性 Reading Claim Graph
        ↓
命理枝 / Lab / 阿布说 / Dream / 剧场 / 题库
```

页面 GET、刷新、切四层、四柱／六柱切换、播放／暂停、进入 Lab 均只读同一代际
对象。只有用户显式发起新推演、输入谱系变化或校准断产生新 revision 时才允许再次
调用模型。

## 9. “高级命理师”资格口径

工程测试通过不等于命理合格。候选至少需要在以下集合持续过线：

- Owner 已知盘：检查事实纪律、整盘主线和可辨认度；
- 陌生参考盘：防止只对一个人过拟合；
- 合成单变量翻转盘：关键变量改变时，相关 Claim 应改变；
- 合成保持盘：无关变量改变时，核心 Claim 不应漂移；
- 重复稳定性盘：同一输入的主解释、证据和时间层不应随机翻转；
- 对抗盘：诱导补关系、后验泄漏、性别刻板、确定灾祸时必须拒绝；
- 强通用 LLM 盲评基准：在专业性、具体性、因果完整性、事实安全和非模板性上
  不能低于用户直接询问通用模型的体验。

合成盘能验证推理一致性和反事实敏感性，不能单独证明现实应事准确；真实 LifeCase
长期回流负责另一半验证。

## 11. 不可破坏原则

1. 一个 Case／Chart／Reading／Claim Graph，不允许模块各造真相。
2. 一次生成、多处复用；读取和播放不触发推理。
3. 盲断与校准断物理隔离，后验信息不得污染盲断。
4. 事实、解释、观察和虚构事件必须可区分。
5. 当前模型不合格就不公开发布，但“不发布”绝不等于“不判断”；私密研发必须给出
   整盘初断，并把局部不确定性放在对应 Claim 上。
6. 高级能力由固定基准、反证和长期验证证明，不由版本号或自我声明证明。
7. V108 是体验正本，V60 是事实与 Runtime 正本；任何一方都不能无声覆盖另一方。
8. Owner 决定产品与正式命理裁决，设计师决定体验意图，Codex 负责可信实现与证据。

顶峰”或把关系成员写成既成作用。错误的事业透干被局部撤下；性情、财富、关系与家庭
继续展示为待经历校准的初断，不再因主路径引用不完整而让整盘失语。

以上段落记录的是 Gemma4 `.014` 的历史产品候选结果，不是 Owner 已裁决的正式命理结论。
同一 Packet 的一次 `gpt-5.6-sol` 原始盲断反而把食伤生财选为有条件主判、食伤制杀判为
受阻，并暴露出旧 Normalizer 按 Packet 顺序重绑合法候选身份的 P0。该 Sol 调用没有写入
数据库；被错误 Normalizer 处理后的结果不得用于模型高低结论。`.015` 阶段已修复并用
反序、无效、重复、fallback、主次翻转和 Claim Graph 回归锁定语义身份。

这已超过“模板或工程边界文案”，但仍只能定级为可审计的结构化初断，尚未达到高级命理师。
当前主要缺口是：乙木承载力尚未把食伤制官杀与食伤生财真正拉开稳定差距；婚恋、家庭、
性情仍会出现从单枚十神跳到心理结论的套话；岁运强度语言也缺少比较基准。

因此下一刀只做专业能力校准：用前沿教师与本地候选的同合同差异发现判法缺口，由 Codex
形成候选方法资产，经 Owner／专业准入后，以合成单变量翻转／保持盘检验日主、机制、
主路径、应事和应期是否随关键结构正确变化；再让本地候选复跑，并把通过复核的判断沉淀为
版本化方法卡和 Gold Reading。教师正文永不自动回流，付费 API 只做里程碑盲检。
不能通过的内容继续局部撤下，但 Agent 必须保留当前整盘工作判断。`publication_allowed=false`
保持不变，直至它稳定超过裸通用 LLM。

## 15. 2026-08-03 根身份矩阵校准

第二组合成实验已经证明，认知系统不能把“同五行”压扁成一个布尔根状态。事实层必须先
保存 `EXACT_DAY_MASTER / SAME_ELEMENT_DIFFERENT_STEM`、藏干位阶和具体坐标；最低门
只回答它能否直接阻止从势，整盘 Agent 再结合月令、生扶泄耗、透藏与组合竞争形成工作
判型。`NOT_DETERMINED` 不是无效、不是无根，也不是最终结论。

这条分层已落实到真实链路：两个合法 Case 各自历法解析、生成 Reading／Packet、调用
Gemma4、经过类型化裁决并写入同一个 append-only 实验 Run。当前干净 Run
`v60-mingli-synthetic-run-f90c01fefacdc663a5ea` 的门级响应全部成立，但模型仍把木根
误归到印星资源、误报藏干位阶和虚构竞争支持；系统修正后才得到安全产品结果，所以模型
独立能力仍为 FAIL。

这一结果也冻结了训练原则：合成实验 Gold 只能定义本实验要验证的最小响应与允许集合，
不得偷偷成为全局 Normalizer；旧 Run 按当时 Profile／Prompt／Evaluator／Gold 重放，
不能用新常量改义；任何能力声明必须区分“系统方法成立”“产品被规则收稳”和“候选模型
独立掌握”。下一矩阵优先校准第一／第二／第三藏干的身份与整盘作用，不回到 Owner 单盘
拟合，也不提前把位阶写成吉凶或根的必然有效性。

## 16. 2026-08-03 合成训练从单盘复盘升级为候选绑定批次

认知系统现在拥有第一条可重复的训练执行链：一个 Suite 定义有序实验集合，一个候选身份
同时锁定 Model Digest、Provider、Profile、Prompt 与 Reading 版本；每个子实验仍保存
自己的原始回答、Normalizer Receipt、Gold 和评价，Suite 只聚合结果与错误簇，不创造
新的命理结论。运行脚本可以无人值守执行；聊天只处理异常解释、专业分歧和 Owner 裁决。

首个藏干位阶 DEV Suite 真实执行两组合法 A／B 实验。两组均通过保持、位阶身份、最低门
响应与正文越界检查，但候选模型四次需要 `DAY_MASTER_REGIME` 修正，并有一次
`WORK_PATH` 修正。认知系统因此获得了比“好／坏回答”更具体的训练信号：下一轮只需验证
日主／根气裁决与路径归槽是否减少修正，而不是继续围绕 Owner 命盘主观润色。

历史批次仍按原 Hash 保存；新 Evaluator 只在独立的 `current_review_projection` 中标记旧
口径，不覆盖 Suite Run 的封存 items、counts 或 error clusters。该投影反向绑定来源
Suite Ref/Hash 并拥有自己的 Hash。只有候选身份完全相同且子 Run 谱系、顺序和定义 Hash
全部匹配时才允许复用。这使未来 Gemma、Qwen 或教师模型可以在同一方法矩阵上公平比较，
但任何模型更换都不能跳过资格流程。
