# V60 高级命理师 Agent 决策与实施正本

状态：`OWNER_APPROVED_IMPLEMENTATION_ACTIVE / TEACHER_DISTILLATION_ACTIVE / PUBLICATION_BLOCKED`

日期：2026-08-02

## Owner 决策

阿布知命当前最重要的问题不是产品外围是否完整，而是系统尚未具备真正的
命理测算能力。后续命理主线必须直接解决“会不会断命”，不得继续以排盘、
证据边界、候选标签、通用观察文案或 UI 完成度代替专业能力。

Owner 授权 Codex 在 `v60/` 内实施必要的清理和重构，目标是把命理测算核心
建设为一个专职的高级命理师 Agent。`v50/` 继续保持只读，任何历史脏改均不
属于本轮范围。

## 架构结论

高级命理师能力不是确定性代码单独生成的文章，也不是让用户把出生日期直接
交给通用聊天模型。正式组合为：

```text
确定性命盘事实
-> 命局分解与专业卷宗
-> 专职命理师 Agent
-> 一次主推理形成完整 Reading
-> 命局原理 / 生命意象 / 人生主题 / 时间趋势
-> Lab 与阿布说复用同一 Reading
```

LLM 是命理师 Agent 的认知核心，不是外围文案工具。V60 负责为它提供准确、
完整、稳定且版本化的专业上下文，并负责保存、复用和投射结果。

## Agent 形态

第一版采用一个专职 Agent，而不是生产路径中的多 Agent 社会：

- 一个命理师身份；
- 一套 Owner 批准的主决策方法；
- 一个完整命局卷宗；
- 一次主 LLM 推理；
- 一个严格但允许真实裁决的结构化输出；
- 一个不可变、可恢复的 Reading；
- 必要时才产生一次明确的领域追问或岁运差量推理。

研发阶段可以离线使用多个模型或批判步骤改进 Prompt，但不得把这些额外调用
复制到普通用户的实时路径。

## 先进模型教师与方法蒸馏路线

Owner 已确认：高级命理师能力不能依赖大量真实八字样本，也不能靠一次更强模型
替系统直接回答。V60 采用“先进模型教师帮助改进系统方法、本地产品候选执行同一
合同”的研发路线：

```text
版本锁定的 Case Packet / Prompt / Schema
-> 前沿教师模型与本地产品候选分别盲断
-> Codex 对比主判、因果链、遗漏、事实错误、套话与反转条件
-> 提取候选方法卡、规则、Prompt、Schema、反例和回归
-> Owner／专业复核准入
-> 合成单变量翻转盘、保持盘、稳定性盘与对抗盘
-> 本地产品候选重新执行同一合同
-> 里程碑式前沿模型盲检
-> 通过资格后才允许产品发布
```

这里的“蒸馏”首先是系统方法蒸馏，不等同于训练模型权重。可沉淀资产包括命局
分解顺序、必要条件、阻断条件、竞争解释、应事映射、Prompt、结构化输出、测试和
Gold Reading。教师模型的正文只是研究证据，不能自动成为 canonical 命理结论；
Codex 可以整理候选资产，只有 Owner／专业复核可以将其准入正式方法。

普通用户实时路径仍只允许一次产品模型调用。前沿教师和 Codex 审读只在研发或
里程碑盲检中使用，并按 Case Packet Hash、Prompt／Schema 版本、模型精确版本、
推理参数与输入谱系缓存，禁止为页面切换重复付费。当前产品资格候选仍是
`gemma4:latest`；Qwen3.8 只作为未来可能的教师或产品候选，未接入、未资格、也
不是当前默认模型。

## 生产调用预算

```text
首次生成一张本命 Reading：1 次主 LLM 调用
打开四个命理枝：0 次
切换 Mingli / Lab / 阿布说：0 次
刷新或重进：0 次
播放阿布讲述：0 次 LLM 调用，TTS 独立
选择尚未生成的岁运窗口：最多 1 次差量调用，随后缓存
提出新的具体命理问题：最多 1 次领域调用
```

相同命盘、方法、知识、模型和时间范围的结果必须复用，不得因页面切换重复
调用。

## 命局卷宗职责

命局卷宗是给 Agent 使用的专业中间表达，不是面向用户的命理内容。它至少
组织以下信息：

1. 四柱、藏干、十神、月令、节气和岁运等确定性事实；
2. 透藏、来源、根位、宫位、相邻与隔位等上下文结构；
3. 生克、制化、通关、阻断及关系成员的有向作用路径；
4. 最多三个主要竞争解释；
5. 每个解释的支持条件、反对条件和缺失条件；
6. 本命与所选岁运之间的差量；
7. Agent 必须完成的专业判盘任务。

命局卷宗不得把五行或十神成员数量伪装成旺衰，不得把候选同时出现伪装成
机制成立，也不得预写事业、财富、关系等通用人生结论。

## 第一版专业输出合同

命理师 Agent 必须形成真实裁决，而不只是排列研究优先级。第一版完整 Reading
至少包括：

1. 命局总纲；
2. 日主状态与全局主要矛盾；
3. 主解释、次解释和被排除解释；
4. 格局成败、救应、调候、体用或用忌中的实际取舍；
5. 三至五条盘面事实到作用结果的因果链；
6. 性格、事业、财富、关系与家庭中的个案化应事；
7. 大运阶段和关键流年的激活机制；
8. 竞争解释与真正有区分力的核验问题；
9. 面向普通用户的四层表达；
10. 阿布说可直接使用的讲述段落和舞台 Cue。

公开正文禁止出现 `Case`、`Hash`、`candidate qualification`、`evidence gap`、
`尚未接线` 等工程用语。专业不确定性必须表达为命理竞争解释或核验问题，
不能替代判断本身。

## 合成命盘是主要验证方法

V60 不依赖大量真实人生档案训练或验证第一版认知能力。正式验证以合法合成
命盘和成组对照盘为主：

- 结构覆盖盘：覆盖月份、日主、根气、透藏、格局候选、阻断和救应；
- 单变量对照盘：只增加或移除一个关键根、来源、通关或关系条件；
- 岁运差量盘：本命不变，只改变大运或流年；
- 冲突盘：让两种理法形成真实竞争，要求 Agent 作出一致取舍；
- 稳定性盘：无关变量变化时，命局主结论不得漂移。

合成验证负责证明规则覆盖、推演一致性、条件敏感性和输出专业性。它不被包装
成现实预测命中率。

## 最低基准与验收

直接把同一出生资料交给强通用 LLM，是阿布知命的最低能力基准。第一版若在
以下维度不能稳定优于该基准，则命理 Agent 纵切失败：

- 命盘事实准确；
- 命局分解完整；
- 主解释明确；
- 因果链具体；
- 不同命盘结论有真实差异；
- 单变量对照能够产生合理翻转或保持；
- 同一命盘多次生成保持核心判断稳定；
- 不使用通用心理文案冒充人生应事；
- 不使用工程边界冒充专业判断。

在本轮完成前，现有 `FORMAL_BOUNDED_READING` 只能代表身份和数据绑定正式，
不能宣称它具备专业断命能力。

## 已实施的第一版主链（2026-08-01 历史基线）

本节保留第一版接线时的事实；其中 4,500 字符、332 项测试与
`NOT_QUALIFIED` 是当日基线，已被后文的可执行裁决纵切取代。

本轮已经把上述决策落成可执行纵切，而不再让固定模板承担断命：

```text
canonical Case / Chart / LifeCase / Reading
-> 完整审计卷宗
-> 紧凑专业 Prompt View
-> 单一 Mingli Agent Provider
-> 类型化整盘输出
-> Runtime 统一语义校验
-> append-only Agent Reading
-> Reading Summary
-> 同一份内容进入命理枝与四／六柱 Scene Player
```

当前实现具备：

- 显式 `POST /api/v60/mingli/stage/agent-reading`，浏览器只能提交既有
  Case、Reading Ref 和 Reading Hash，不能提交 Prompt 或正文；
- 一次主模型调用，同一代际键重复请求直接复用；
- 完整卷宗保留 lineage、来源和 Hash，模型只读取不超过 4,500 字符的紧凑
  专业视图；
- 根候选、明干同类和印星生扶分栏，模型必须原样确认，不能把印当根；
- 固定两个竞争解释、一个主路径、五个人生领域、生命意象、大运和流年；
- 大运与流年的坐标和关系证据分层校验，流月不进入第一版六柱 Agent；
- 六冲／六合只有成员证据时，任何“已经合动、冲开、化解、提升”等作用结论
  都必须被拒绝；只有明确的条件式解释才可留在待审 Agent 输出中；
- Agent 输出不能改写 canonical 事实，持久化记录明确保留未审阅解释身份；
- GET、刷新和命理四层切换读取缓存，不触发第二次 LLM 调用；Lab 已与命理枝
  共用四／六柱舞台，但 Agent 语义投射和阿布说讲述接线尚未进入本轮；
- 没有合格结果时，前台不再显示事业／财富／关系通用模板。
- 模型资格与结果投射使用同一发布开关；当前状态为 `NOT_QUALIFIED`，即使
  运维误开生成环境变量也只能得到 `UNQUALIFIED`，不能调用模型或把历史失败
记录投射为正式 Reading。

本轮最终验证包括 332 项后端测试、Ruff、TypeScript/Vite build、Runtime
Architecture、源码维护审计，以及真实 Desktop Chrome。Chrome 从刘晋档案叶进入
命理枝，逐一检查命局原理、生命意象、人生主题、时间趋势和六柱舞台；四层均未
回退到旧领域模板，浏览器控制台无错误。

架构接通不等于具备高级命理师能力。本轮使用 Owner 当前真实命盘
`丁巳／乙巳／乙丑／乙酉` 做了内容级资格审读。

在 v5 紧凑合同下完成一次完整结构化输出：输入 2,005 tokens、输出 2,416

- 在关系领域把大运子水误称为流年；

研发证据，不进入当前 Reading。

## 对 Owner 两个问题的正式回答

### 能否做成高级命理师

有信心，也具备继续实现它所需的架构与验证能力；但“高级”不能靠自我声明。
现在完成的是可信 Agent 主链和第一轮模型淘汰，不是高级命理师能力本身。
只有陌生命盘、合成单变量对照盘和稳定性盘持续超过强通用 LLM 基准后，才允许
把状态改为合格。

### 核心是否应直接做成 Agent

是。命理测算核心应当就是一个专职 Mingli Agent，而不是固定规则文章，也不是
实时多 Agent 群。系统相对“直接问 LLM”的意义是：

- 输入不是裸出生资料，而是确定性排盘和专业分解后的整盘卷宗；
- P0 命理事实由系统计算和校验，LLM 负责真正的整盘认知与取舍；
- 输出必须在竞争解释、因果路径、人生应事和岁运分层中自洽；
- 同一结果可恢复、可比较、可复用到命理枝、Lab、阿布说与游戏；
- 合成对照盘可以证明结论该翻转时翻转、该保持时保持；
- 首次一次调用，随后零调用复用，避免每次页面操作重新问模型。

## 第二条已实施纵切：可执行专业裁决

第一版的问题不是没有候选，而是只告诉模型“检查什么”，没有强迫它逐项回答，
所以食伤制官杀、食伤生财等机制最终仍停留在并列可能。`.014` 阶段已把方法卡变成
可执行裁决：

```text
每个候选机制
-> 每个必要条件逐项 SUPPORTS / CONDITIONAL / OPPOSES / UNRESOLVED
-> 服务端重算 SUPPORTED / CONDITIONAL / BROKEN / UNRESOLVED
-> 选择主判与备选
-> 说明胜负检查项
-> 给出可验证的翻盘条件
-> 投射到同一份 Claim Graph
```

服务端不接受模型自报的状态和置信度。阻断条件为 `OPPOSES` 时该机制必为
`BROKEN`；阻断条件未查清时必为 `UNRESOLVED`；条件尚未完全闭合时只能是
`CONDITIONAL`。即使全部机制失败，Agent 也必须给出低置信度整盘工作假设，不能用
“证据不足”替代断盘。

候选覆盖也成为显式合同：零候选为两个 fallback；一个候选为候选加 fallback；两个
候选逐一比较；超过两个候选时，未进入 H1/H2 的项目必须出现在淘汰台账中。这样系统
能够证明自己看过哪些路径、为何暂不采用，而不是只展示模型碰巧写出的两个答案。

局部语义错误不再使整盘消失。错误根气、透藏、关系、比肩数量或岁运坐标由 Claim
Graph 撤下对应 Claim；其余可成立内容继续展示。只有不可解析结构、canonical
typed fact 漂移或谱系错误仍属于整盘失败。

真实 Owner 命盘 `丁巳／乙巳／乙丑／乙酉` 已完成 Gemma4 `.014` 推演，落成
`v60-mingli-agent-reading-b11fc2f2c55feffdfeb2`：输入 6,298 tokens、输出
3,896 tokens、耗时 84,133 ms。当前工作主判为食伤制约官杀，备选为食伤生财；
命理枝直接显示支持点、限制点和主次理由，Lab 展开逐项判法与翻盘问题。

Claim Graph `.009` 不再让旧的候选边界覆盖新裁决：方法 ruling 的命盘依据会进入主判，
有条件的原局做功路径可以继续表达；丙午流年中的丙伤官按流年层判断，不再被误报为
原局透干错误；“化解冲突”也不会被误读为技术性的“解冲”。原局、大运和流年现由胜出
方法及其限制项重新投射：保留庚子、丙午及对应十神的真实显露，但不再重复“冲突达到
顶峰”，也不把子丑六合成员直接说成已经做功。事业因把藏丙误写成透出而单条撤下；
性情、财富、关系和家庭仍展示为待经历校准的初断，因为它们尚未从本轮主路径完整推出。

这证明系统已经从“列候选”进入“能下一个可复核工作初断”，但仍没有达到高级命理师。
最主要的不足不是不敢说，而是食伤制官杀与食伤生财的胜负仍依赖偏粗的承载／显藏判断，
五域中的婚恋、家庭和性情仍会出现十神套话。

## 首次前沿教师对照与 P0 纠正

同一 Owner Packet `v60-mingli-agent-packet-9e171728a96a776f8692` 已进行一次
付费 `gpt-5.6-sol` 研发对照，不写数据库、不进入产品 Reading：输入 7,807 tokens、
输出 5,053 tokens（其中 reasoning 1,756）、耗时 69,740 ms，按当次用量估算约
`US$0.190625`。对应 Gemma4 `.014` 基线为输入 6,298、输出 3,896、耗时
84,133 ms。

Sol 原始输出把 `E010 食伤生财` 选为有条件主判，把 `E009 食伤制杀` 判为受阻；
Gemma4 基线则选择相反主次。这种分歧本来正是系统需要研究的专业问题，但审计发现
服务端旧 Normalizer 会按 Packet 顺序强行重绑方法卡，导致 Sol 的候选名称、正文、
逐项 ruling 和主次身份被错配。任何基于该错误 Normalized Reading 的比较都无效。

`.015` 阶段先修复这一 P0：合法且唯一的方法卡身份先被保留；无效或重复引用只在
对应假设上中性重建并记录问题；服务端若因逐项 ruling 调整主次，翻转信号会跟随原
假设迁移。反序、单候选加 fallback、无效引用、重复引用、零候选及 Claim Graph
投射均有回归。由此，后续教师对照比较的是命理方法，而不再比较被服务端篡改后的
伪结果。

一次内部专业量表审读将 Sol 原始结果评为约 6.2/10、Gemma4 基线约 3.4/10。
这个分数只用于确定研发优先级，不是产品准确率，也不是高级命理师资格。Sol 更能
形成结构化中间判断，但仍明显缺少身弱／从势竞争、三合金局、调候、关系与家庭因果链，
以及六柱岁运的完整推演，因此同样不能直接作为正式答案。

## 第三条已实施纵切：首批专业方法蒸馏

本轮没有把教师模型正文复制给 Gemma，也没有继续追加抽象 Prompt。系统新增首批
版本化候选方法资产 `v60.mingli-agent-method-distillation.001`，先解决真实 Owner 盘
已经暴露的三个专业短板：

1. `REGIME_WEAK_VS_FOLLOW_TREND_001`：强制比较普通身弱、从势与假从竞争；无有效根
   但仍有浮透比肩、弱藏印或合化未定时，不能仅凭“无根”直接判从或跳到喜忌；
2. `OUTPUT_WEALTH_VS_CONTROL_KILLING_001`：把宽泛的“食伤制官杀／食伤生财”拆成
   食神→七杀、伤官→七杀、伤官→正官、食神／伤官→正财／偏财等精确十神子路径，
   每条路径绑定本盘显藏坐标和逐项正反条件；
3. `RELATION_SPOUSE_STAR_AND_PALACE_TWO_AXIS_001` 与
   `FAMILY_SCOPE_AND_TWO_AXIS_001`：关系必须同时检查配偶星与夫妻宫，家庭必须先声明
   原生家庭、当前家庭或亲子范围；单枚偏印不得再直接生成“精神共鸣／安全感”故事。

方法卡按 `pattern_ref` 绑定，不依赖 Packet 中临时的 `E009/E010` 顺序。共享的来源和
日主承载检查不能单独决定两条机制胜负；食伤制杀侧重点名目标身份、显藏可达与阻断，
食伤生财侧重点名财目标承接、印制食伤与比劫争财。六组纯函数回归已经覆盖根气、支持、
目标显藏、财富目标、财富桥、比劫竞争和男女配偶星通道的单变量 flip／hold。

Claim Graph `.010` 同时增加专题方法门。关系／家庭从单枚十神直接跳到心理故事时只撤下
对应 Claim；日主、主判、其他领域和岁运继续存在。当前输出合同尚无 typed axis 选择与
正向专题规则，所以出现“财星／夫妻宫／当前家庭”等关键词也不能冒充方法完成；这两域在
正向方法准入前保持私密研究。夫妻宫中写入实际不存在的十神仍按具体柱位冲突撤下。

### 本地 Gemma4 `.016` 复测

第一次复测在旧 4,096 输出上限处截断 JSON，没有写入 Reading。Gemma 本地服务配置随后
升为 `v60.model-serving.gemma4-mingli-agent.002`，输出预算为 5,200，并明确限制逐项
rationale／falsifier 篇幅。早期成功样本虽首次把主线改为食神生财，但增加“无根身弱时
承载不得无条件 SUPPORTS”后，Gemma 曾再次把制杀放回主线。复盘发现旧排序仍在数全部
SUPPORTS，允许“官杀存在”掩盖“显藏可达、阻断与同层作用尚未解决”。

最终排序改为先比较每条路径专属决胜项的最弱一关，再比较专属项完整度；共享的来源和
承载不再参与抢占主线。最终 append-only Reading 为：

```text
agent_reading_ref: v60-mingli-agent-reading-d0aab120f2ffd51cc377
chart: 丁巳／乙巳／乙丑／乙酉
model: gemma4:latest
input_tokens: 9690
output_tokens: 3700
duration_ms: 84061
server_issue_keys: []
```

最终结果把日主判为 `WEAK`；`E010 食神生财` 为 `CONDITIONAL` 工作主判，财目标可达与
印制食伤裁为 `SUPPORTS`，比劫争财与日主承载裁为 `CONDITIONAL`；`E009 食神制杀` 降为
`UNRESOLVED` 备选，虽然七杀目标存在，但显藏可达和同层作用只有条件成立，其他阻断仍未决。
两条路径的 `DAY_MASTER_CAPACITY` 均为 `CONDITIONAL`，不再把两处浮透乙比写成可持续承载。
这与首次 Sol 教师审查的主次方向一致，而且是由本地模型逐项 ruling 与服务端专属决胜规则
共同得出，不是把教师正文复制成答案。

但本次结果仍未取得高级命理师资格。Gemma 的财富段又把比肩扩写为“人际合作”，性情、
事业和财富没有随服务端主次翻转重新引用食神生财主路径；关系与家庭虽写出文字，却没有
结构化的正向专题规则。Claim Graph 现在要求具体十神子路径，不再接受笼统“食伤／财星／
官杀”；并把“人际合作”套话撤下。关系与家庭在 typed axis 与正向判法正式准入前统一留在
私密研究层，不能再靠关键词伪装两轴完成。岁运坐标可恢复，但仍缺真正的应期强度裁决。

因此本轮的准确结论是：系统已从“泛候选＋十神套话”推进到“具体十神路径、身弱承载和
跨路径专属短板共同决定主判”，并能阻止主次翻转后的旧应事继续冒充结论；但尚未达到高级
命理师。`publication_allowed=false` 保持不变。

现有“事实向量级反事实测试”已经升级成第一组可由历法引擎独立解析的合法成对命盘。

首组对照将时柱从己巳变为丙寅。旧系统已经看见 B 的 `hour支藏甲` 根候选，却不能决定

从势，不能证明身强、根可用、用神、做功或吉凶；不满足最低规则且没有明确失效证据的
