# V60 合并前双主线产品决议

Status: `ACTIVE_PRODUCT_AUTHORITY`

Date: `2026-07-31`

本文件取代此前的“五单元并行推进”和增量式 Slice 清单，作为设计原型
合并前唯一有效的产品方向。V60 从现在起只追求两个产品结果：

1. **阿布命理具备高级命理师级的命运测算能力。**
2. **阿布梦境成为命理剧情完整、题库完整、游戏引擎成熟，并有受控
   AI NPC 真实参与的游戏系统。**

Lab、阿布说和小剧场不再拥有独立产品路线：

- Lab 只服务于专业规则研究、案例复核、盲测和准入；
- 阿布说只负责表达同一份正式 Reading；
- 小剧场只服务于梦境剧情演出与已批准内容的传播。

任何工作如果不能在同一轮形成上述两条主线之一的可见能力，就不进入
当前开发。

## 立即停止

- 停止新增只展示 Gate、Hash、边界或“仍然缺什么”的产品页面。
- 停止把架构整理、版本号增长、测试数增长当作功能完成度。
- 停止复制同一种 Dream Episode 冒充内容扩展。
- 停止把运行时 Question 副本计作题库规模。
- 停止把预写 `npc_choice_id` 称作 AI NPC 决策，把预封存结果称作动态
  世界模拟。
- 停止五个产品单元各自形成路线、Reading、Case、剧情或状态。
- 停止与两条主线无关的手机端、部署、Server 13、泛化平台和视觉细节
  工作。
- V50 继续冻结，只读参考；不得修改、提交或把其 Runtime 接入 V60。

必要的底层修复只有在它直接阻断当前纵切时才能进入，并且必须与可见
产品结果在同一轮交付。

## 主线一：高级命理师级命运测算

### 当前 Review 结论

V60 当前是可信、可追溯、能够诚实弃权的命理事实与研究底座，还不是
能够独立完成命运判断的高级命理师。

| 能力层 | 当前完成度 | 结论 |
| --- | ---: | --- |
| 排盘与基础事实 | 80–85% | 已具备实用基础 |
| 结构证据整理 | 55–60% | 有价值，但覆盖很窄 |
| 专业命局判断 | 10–15% | 尚未形成完整判断 |
| 大运流年推演 | 约 10% | 只有坐标与成员重叠 |
| 人生领域结论 | 约 5% | 目前只是观察窗口 |
| 真实案例校准 | 0% | 没有可报告准确率 |
| 高级命理师总体目标 | 约 25–30% | 尚未达到“会断命” |

以上完成度是本次功能审计的产品估算，不是测算准确率，也不是行业统计。

### 已经真实具备

- 阳历／农历出生输入、四柱计算、真实 Case 创建与切换；
- Case、Chart、LifeCase、Reading 的版本化、追加保存与复算；
- 天干五行、阴阳、藏干成员和完整十神矩阵；
- 本命六冲、六合的成员关系；
- 未加权五行／阴阳成员统计，并明确不冒充旺衰；
- 明干与藏干的同干、同五行来源坐标；
- 五类结构候选及其证据、竞争者和缺口；
- 当前大运、流年、流月坐标及其成员重叠；
- 事业、财富、关系三个有边界的观察领域；
- Fact、Vector、Profile、Reading、Decision 的可追溯与可复算；
- 证据不足时对旺衰、根气可用性、关系作用、有效做功、吉凶和概率
  的明确拒绝。

Gemma4 当前只被允许排列“优先核查哪个结构候选”，不能创造命理事实，
也不能完成专业断语。

### 决定性缺口

1. **排盘边界不完整**

   真太阳时仍为 `not_applied`；尚无出生时刻不确定、子初换日流派差异、
   多盘比较和完整历法差异说明。
2. **干支关系不完整**

   只有六冲、六合成员关系；尚缺天干合冲、三合、三会、半合、刑、害、
   破，以及成立、破坏和作用条件。
3. **核心命局模型缺失**

   月令、司令、季节容量、得令得地得势、根气可用性、日主旺衰、寒暖
   燥湿、调候、格局、破格、用神与忌神尚未形成获准规则。
4. **机制作用、竞争和反证缺失**

   当前结构候选主要是成员共现，不能判断流通、阻断、救应、容量、
   主次、合化、反制或有效做功。
5. **时间推演尚未成立**

   当前只有大运／流年／流月坐标；没有激活条件、作用方向、应期、
   持续期、事件类型和历史回验。
6. **完整测算输出缺失**

   尚不能生成整盘画像、人生主线、阶段变化、事业财富关系判断，以及
   对用户具体问题的直接回答。
7. **专业知识和校准缺失**

   当前核心 Profile 仍为 `professionally_reviewed=false`；未形成正式
   来源材料、双专家审定、分歧流派、盲测案例和真实结果校准。

### “高级命理师级”完成定义

一次正式测算必须从同一个可复算 Reading 输出：

- 确定事实与排盘差异；
- 命局主结构、竞争结构和替代解释；
- 旺衰、调候、格局、用忌及其证据；
- 支持证据、反证、未决条件和弃权理由；
- 当前大运及关键流年阶段；
- 事业、财富、关系等领域的阶段性判断；
- 对用户具体问题的直接回答；
- 每项判断的适用范围、观察点和可回验条件。

所有专业规则必须拥有版本、适用范围、成立条件、阻断条件、作用方向、
反证和专业来源。不同流派或专家分歧必须作为竞争解释保留，不能静默
混成一句确定结论。

正式对外声称达到高级命理师级之前，建议采用以下内部验收草案：

- 200 个匿名、经专家标注的真实 Case；
- 其中至少 100 个为开发过程未见的盲测 Case；
- 两位独立命理师和一位分歧仲裁者；
- 确定输入下的排盘事实错误率为 0；
- 规则适用与证据引用一致率不低于 95%；
- 核心结构判断与专家仲裁一致率不低于 80%；
- 证据不足时正确弃权率不低于 95%；
- 所有展示结论 100% 可追溯、可复算、可版本回放。

样本量和阈值必须由 Owner 与专业顾问共同确认；它们不是行业标准，也不
代表当前系统已经达到相应准确率。

真实结果校准完成前，禁止显示“准确率”或伪造概率。

### 合并前第一条命理纵切

停止继续制作新的证据缺口展示页。选择一个已授权真实 Case，直接完成
一份由专业命理师逐项复核的完整 Reading：

```text
完整排盘边界
-> 月令与季节容量
-> 根气与日主旺衰
-> 一个完整关系作用规则族
-> 机制竞争、阻断与反证
-> 当前大运／流年作用
-> 一个真实人生领域的阶段判断
-> 对用户问题的直接回答
-> 专业复核与可回验观察点
```

这一纵切必须在真实命理测算页面可见，Lab 只能展开同一 Reading 的规则
与证据，阿布说只能表达同一 Reading。三者不得各造一套答案。

## 主线二：完整的 AI NPC 命理剧情游戏

### 当前 Review 结论

阿布梦境当前是可靠、真实可玩的“判断—等待—对证”Alpha 纵切，但还
不是可持续游玩的剧情游戏，也不是多 NPC 模拟世界。

| 能力层 | 当前完成度 | 结论 |
| --- | ---: | --- |
| 存档、恢复、世界时钟 | 约 90% | 可靠 |
| 单章核心循环 | 约 75% | 已完整可玩 |
| 视觉与氛围 | 约 55% | 精致原型 |
| 剧本质量 | 约 55% | 逻辑清楚，戏剧性弱 |
| 剧本内容量 | 约 20% | 不足一小时 |
| 题库系统 | 约 15% | 主要为固定题 |
| 玩家行动能动性 | 约 25% | 能判断，不能真正行动 |
| 长期留存 | 约 20% | 完成后断粮 |
| 多 NPC／AI NPC | 约 5% | 用户侧基本未实现 |
| 完整游戏总体目标 | 约 35% | 可玩纵切，不是成熟游戏 |

以上完成度是本次功能审计的产品估算，不是用户留存、内容质量或 AI
能力的统计测量值。

### 已经真实具备

- 真实 Grove 公开事业、财富、关系三棵树；
- 当前公开 5 章、15 个选项，首次内容约 30–45 分钟；
- 两个源码 Registry 共有 10 个 authored 模板、10 个原创问题和 30 个
  选项；当前公开 Grove 使用其中 5 个，系统共有 4 名持久化 Actor；
- 严格 Encounter 状态机、权威世界时钟、事件结算、防重复命令、
  刷新与进程重启恢复；
- AnswerSeal、独立结果、Reveal、Reconcile 和回访闭环；
- 玩家预测不能倒写已经独立发展的世界事实。

### 当前真实短板

1. **题库规模被运行时副本掩盖**

   数据库 545 条 Question 中只有 10 个原创模板，另外 535 条是世界
   时间窗口副本；当前公开 Grove 实际只有 5 个原创问题。
2. **只有一种线性玩法**

   所有 Episode 都是“两叶→一枝→一花→封存→等待→一果→复盘”，
   没有第二种玩法、探索、地点、资源、任务或条件分支。
3. **预测选择不是行动选择**

   玩家答案只改变预测复盘，不改变可获得信息、人物承诺、下一场景或
   路线。
4. **世界结果仍是预写结果**

   世界时钟与结算是真的，但结算提交的是 Episode 预先封存的固定结果，
   尚非角色状态和行动演化出的结果。
5. **AI NPC 尚未形成**

   当前 `npc_choice_id` 是剧本固定配置。四名 Actor 彼此不互动，也没有
   目标、知识边界、记忆、关系、日程、行动生成或 NPC-to-NPC 事件。
6. **真实状态污染与无界增长**

   Opportunity 重复物化已经制造大量未游玩副本；缺少显式
   `actor_state_delta` 时，闻溪、禾央、照宁会错误继承砚舟的“测量
   间歇水流”活动。进入多 NPC 开发前必须修复。

### 成熟梦境游戏完成定义

#### 命理剧情

- 剧情从同一份正式 Mingli Reading 的事实、候选解释或有边界未知出发；
- 命理不能预写 NPC 结局，Dream 也不能反向制造命理真相；
- 每条主线具有人物动机、冲突升级、关系变化、秘密、阶段转折与结局；
- 预测选择不能改写事实，但玩家在世界中的真实行动可以产生可追溯的
  因果后果。

#### 完整题库

- 原创模板与运行时实例严格分开统计；
- 每题具有领域、主题、证据模式、认知能力、难度、前置状态、适用角色、
  合法选项、结果判别和版本／审核状态；
- 支持条件题、状态变体、剧情分支、难度梯度和重复游玩去重；
- 私人问题能够在明确权限下被理解和映射，而不是只读取用户手选领域；
- 内容作者能够预览、校验、审阅和版本化发布题目，不在服务代码里散落
  硬编码文案。

#### 成熟游戏引擎

- Actor、场景、位置、关系、承诺、资源、任务和 WorldEvent 都是权威
  持久化状态；
- 支持交谈、询问、观察、提出方案、等待、移动等真实行动；
- 行动改变信息、关系、承诺与后续可选场景，并留下可回放因果链；
- 等待某个结果时，玩家可以去其他人物或地点继续行动；
- 世界结果由规则、角色状态和已发生行动推导，不由玩家的预测答案决定；
- 刷新、重进和服务重启继续恢复唯一 canonical World。

#### 受控 AI NPC

- 每个 NPC 拥有身份、目标、偏好、知识边界、记忆、关系与承诺；
- NPC 只感知自己有权知道的事件，并能形成有依据的意图和行动提案；
- LLM 可以生成受约束的对话、计划和候选行动，但不能直接写世界事实；
- 服务端规则验证行动权限、资源、时序、知识与安全边界后才可提交；
- NPC-to-NPC 互动必须形成真实 WorldEvent，而不是仅存在于文案；
- 相同局面允许因角色状态和行动形成多个合法结果，同时保持可复现、
  可审计和失败可恢复。

### 合并前第一条梦境纵切

设计原型从“照宁第二章：三人协作”开始接入，而不是给现有单循环换皮：

- 照宁与两名具名 NPC；
- 三者分别拥有目标、已知信息、记忆、关系和承诺；
- 玩家至少可以交谈、询问、提出方案和等待；
- 同一初始局面可由角色状态演化出至少 3 种合法结果；
- 玩家行动改变证据、承诺和下一场景，但预测答案不能改写事实；
- 围绕该局面交付 6–8 个条件问题和 2–3 章可分支剧情；
- 等待期间可进入另一个人物或地点；
- 完成真实数据库、真实页面、刷新与服务重启的全流程验证。

本纵切开始前只允许两项直接阻断修复：

1. 同一 Actor／Episode／有效时间窗口按稳定 identity 幂等物化；
   过期或未使用副本不得污染活跃 Catalog，原创题与实例分开计数；
2. 删除砚舟专用状态默认值并修复已污染的三名 Actor。事件允许显式
   no-op；只有声明改变 Actor 状态的 WorldEvent 才必须提供合法的
   `actor_state_delta`。

## 合并前必须看到的产品结果

设计原型可以分模块逐步接入，但不得另建第二套 Case、Reading、Actor、
Question、Encounter 或 World。

合并前必须至少证明：

1. **命理：**一个真实 Case 能从排盘事实走到一份经专业复核、包含阶段
   命运判断和直接问题回答的完整 Reading。
2. **梦境：**一个三 NPC 场景能产生真实互动、动态状态变化、条件问题、
   分支剧情和多个合法世界结果。
3. **共享：**梦境只消费同一 Reading 中明确允许进入剧情的事实和未知，
   不创建第二套命理结论。
4. **恢复：**刷新、重进和服务重启恢复同一份 Reading 与同一个 World。
5. **表达：**设计原型字段全部映射到 canonical 数据；页面不再用视觉
   文案伪装尚未实现的推理或模拟。

后续每轮只回答两个问题：

- 高级命理师能力是否增加了一个真实、可复核的判断？
- 阿布梦境是否增加了一个真实、可玩的剧情／题库／引擎／AI NPC 能力？

如果两个答案都是否，本轮不做。
