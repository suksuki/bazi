## 用户进入与第一眼

正式路径保持：

```text
生命树 / 命理枝
→ 阿布 Lab
→ 合成命局训练区域
→ 选择“封存复盘”或“专业盲审”
```

第一眼仍应处在阿布知命的世界里，而不是进入开发者后台。需要让用户立即理解三件事：

1. 这里研究的是一个明确的命理方法问题；
2. 当前看到的是合成命局，不是真人档案；
3. 训练要先独立作答，再看系统答案。

可以由阿布用一句克制的引导建立节奏，例如：

> 先别看答案。我们只看命盘，看看哪一处证据真的改变了判断。

阿布在这里是研究向导，不是替 Owner 作答的权威裁判。阿布说可以复用为可选语音讲解，
但首轮不要求每个实验都生成音频。

整个训练场需要同时表达两个比较轴：

```text
命盘轴：样本一 ↔ 样本二
同一轮里，证据与判断是否按控制变量发生变化

训练轴：Run 1 → Run 2 → Run 3
方法、Prompt 或模型变化后，原始模型是否减少了错误与服务端修正
```

当前 V60 只表达了命盘轴的一部分，训练轴还没有形成体验。技术 Ref、Hash、Token 与完整
版本号应进入最后一级证据抽屉，不要常驻占据视觉中心。

## 首轮四个连续场景

### 1. 合成实验书架

目的不是展示模型胜率，而是选择要研究的“方法问题”。每个实验只需显示：

- 方法族与一句问题；
- `DEV / QUALIFICATION / HOLDOUT` 身份；
- 是否有封存运行；
- 当前可做动作：继续盲审、查看已揭晓复盘或等待实验；
- 上次审阅位置与完成状态。

不要显示排行榜、总分、胜率仪表盘或“高级命理师百分比”。首轮只把 `DEV` 做成完整
可互动流程；`QUALIFICATION / HOLDOUT` 在书架显示锁定身份与说明，不进入整组盲审。
后续只有 Owner 明确开启后才扩展，`HOLDOUT` 在此前不得展示答案。

课题按专业问题组织，而不是按 Run ID 组织。首批可以在原型中预留：

- 根气位阶；
- 同字与同元素；
- 冲合竞争；
- 明确失效反例；
- 多根竞争；
- 岁运不得回写原局。

### 2. 单盘盲判桌

创建 review 时只随机一次“样本一／样本二”的对应顺序并随 review 封存；刷新、返回和
恢复都不得重新排序。揭晓前不显示 A／B、实验目标和 Gold。舞台周围只保留完成专业
判断所需的结构化动作：

- 日主工作判断；
- `普通身弱 / 从势工作判断 / 未决`；
- 有效根状态与证据坐标；
- 主判依据；
- 最强竞争解释；
- 哪一条新证据会让判断翻转。

证据引用应尽量通过点击柱、干、支、藏干和已准入关系完成。自由文字是说明，不应成为
唯一证据绑定方式。锁定后不能原地修改；修改必须创建新的审阅 revision。

建议自然呈现以下交互节奏：

```text
观察样本一
→ 点选证据
→ 完成结构化判断
→ 锁定
→ 观察样本二
→ 锁定
```

锁定前可显示“尚有哪一项未完成”，但不要把体验做成问卷表格。

### 3. A／B 揭示对照

两份判断都锁定后，才允许揭示实验。仍使用同一个 Scene Player，以切换、局部形变和焦点
完成对照，不并排创建两个 Canvas。

只需要三个明确过滤动作：

```text
只看变化
只看保持
查看全部
```

视觉语义必须区分：

- 输入真正改变的坐标；
- 应当保持的本命事实；
- 因完整柱变化而同时发生的连带差异；
- 判断发生变化的位置；
- 已准入的关系成员事实；
- 尚未证明作用的关系，只能保持中性，不得演成“发生做功”。

第一组实验是完整合法时柱改变，不是单一根气因果实验。原型不应通过动画暗示“只因为一
个根，整盘就必然翻转”。

### 4. 三轨裁决与方法候选

揭晓后，每个关键判断分成三条不可混淆的轨道：

| 轨道 | 用户需要理解的内容 |
| --- | --- |
| 原始模型 | 模型在任何服务端修正之前真正回答了什么 |
| 产品归一化 | 哪些字段由已准入服务端规则修改，产品最终显示什么 |
| 专业裁决 | Owner／专业审阅者认为什么成立、什么仍应未决 |

每个字段需要能识别来源：`MODEL / SERVER_RULE / PRO_REVIEW`。总状态也必须拆开：

```text
实验有效性：VALID / INVALID
模型独立能力：PASS / FAIL / NOT_EVALUABLE
产品结果安全：SAFE / UNSAFE
```

不能用一个绿色的“九项通过”掩盖“模型靠服务端修正才得到安全结果”。Gold 也不是不可
质疑的神谕；专业审阅者可以要求修订，但只能新建下一版 Gold，不能回写旧运行。

每个专业字段都需要提供明确裁决动作：接受模型原断、接受系统修正、改为专业结论、
标记未决、绑定证据坐标、锁定 revision。锁定后仍能查看上一版，但不得原地改写；新的
判断只能形成下一 revision。

首屏应先回答四件事，再进入证据细节：

1. 实验结构是否有效；
2. 该改变的判断有没有改变；
3. 不应变化的事实有没有保持；
4. 模型独立完成了，还是系统修正后才安全。

当前真实运行可以作为原型样例数据；它们不是产品里永久硬编码的固定四行：

| 运行 | 保持 | 响应 | 真实含义 |
| --- | ---: | ---: | --- |
| Run 1 | 6/6 | 1/3 | 模型没有完成全部预期响应 |
| Run 2 | 6/6 | 3/3 | 产品结果响应成立，但仍经过服务端修正 |
| Run 3 | 6/6 | 3/3 | 仍有服务端归一化，不能宣称模型独立通过 |
| Run 4 | 6/6 | 3/3 | 首次封存字段级原断；可明确看见模型究竟错在哪一字段 |

请设计一条轻量、可展开的封存历史。选择旧运行后仍在同一个舞台复盘；时间线优先告诉
用户“模型少犯了什么错、仍在哪里依赖修正”，而不是先展示长 Ref。

裁决结束后才出现“形成方法候选”：

```text
当【前提】成立，
并且【竞争条件】不存在／已处理时，
只允许推出【最小结论】；
不得推出【越界结论】；
还需要用【反例矩阵】验证。
```

动作首轮只需：

- 保存方法候选；
- 要求补反例；
- 本轮不形成方法。

结果只能是 `DRAFT_CANDIDATE`，不得自动进入规则库、Prompt、Gold 或正式 Reading。

## 体验状态与恢复

设计不必向用户展示工程枚举，但原型必须覆盖这些真实状态：

```text
REVIEW_READY
→ BLIND_A
→ A_LOCKED
→ BLIND_B
→ PAIR_LOCKED
→ REVEALED
→ COMPARING
→ ADJUDICATING
→ METHOD_CANDIDATE / NO_METHOD
→ REVIEW_SEALED
```

还需覆盖：

- 无实验、实验尚未离线运行；
- 正在读取；
- 某个样本读取失败但旧舞台仍在；
- 实验定义漂移，禁止用新定义解释旧结果；
- `INVALID_EXPERIMENT`；
- `PRODUCT_SAFE_MODEL_FAIL`；
- 刷新、前进、后退恢复到同一实验和同一锁定状态；
- 已锁定回答不得因刷新重新变为可编辑。

还要补全与原型整体的进出关系：未完成审阅离开 Lab 后如何继续；封存后如何返回实验
书架或命理枝；选择“要求补反例”后，书架如何出现一个待补实验而不是立即假装训练完成。

## 盲审与 Gold 的硬边界

- 揭晓前不显示实验题目中的答案暗示、目标方法、A／B 对应、Gold、模型输出或 PASS／FAIL；
- 盲审 API 必须物理上不返回这些字段，不能只靠 CSS 隐藏；
- 两盘分别送入模型，A Packet 不含 B，B Packet 不含 A，二者都不含 Gold；
- 浏览器可以提交专业审阅，但不能由此触发模型调用；
- 揭晓后若需重跑，必须形成全新的干净 Run；
- `QUALIFICATION` 整组完成前不逐盘揭晓；
- `HOLDOUT` 只有 Owner 明确开启后才可揭晓；
- 所有审阅、Gold 和方法候选 append-only，历史不可覆盖。

## 视觉与演出要求

- 保持原型的温润、克制、有生命感；避免 HUD、模型监控台和密集工程术语；
- `PRODUCT_SAFE_MODEL_FAIL / SERVER_RULE / PRO_REVIEW` 等机器枚举只进入证据抽屉；
  首屏请给出温润、准确的用户文案，例如“模型还没独立掌握，系统已先把结果收稳”；
- 原断差异先按“根状态／判型／主次解释／做功路径”等专业问题分组，只展示决定性的
  before／after；完整 hypotheses、Hash 和长结构化对象必须进入最深证据层，不能形成字墙；
- 一个四柱／六柱舞台贯穿盲看、揭示和复盘，相机与空间方向保持一致；
- 改变项可以被引动，保持项应安静稳定；
- 藏干位阶要能被看懂：第一藏干、第二藏干、第三藏干不能只藏在文字表格里；
- 用户点选证据时，舞台对象与判断卡建立清晰但克制的空间联系；
- 阿布具有待机、观察、引导与揭晓状态，但不能抢走命盘作为视觉中心；
- 阿布第一轮使用 `Dylan`，多多不必为了热闹进入实验室；
- 阿布至少能讲解“实验为何成立／两盘真正改变了什么／模型学会与未学会什么”；
- 角色状态至少覆盖 `IDLE / PREPARING / READY / SPEAKING / PAUSED / FAILED`；
- 如果使用语音，脚本、字幕、角色和舞台 Cue 继续服从同一个音频主时钟；
- 当前只验收 Desktop Chrome，建议至少覆盖 1440×900 与 1280×800。

## 首轮明确不做

- 不做浏览器随机八字生成器；
- 不做浏览器一键调用模型；
- 不做自动训练、微调或 Prompt 自动发布；
- 不做模型排行榜、胜率和积分游戏；
- 不开放自由聊天替代结构化专业裁决；
- 不自动晋升方法、Gold 或正式命理规则；
- 不把合成结构实验称为真人应事准确率；
- 不做手机、iPad 或书籍竖屏版本；
- 不要求首轮把所有命理方法矩阵都画完。
