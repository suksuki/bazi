# V60 Return Encounter Slice

## Product question

The second vertical slice proves that Abu Dream is a continuing world rather
than a one-use question screen:

```text
first fruit reconciled
-> viewer voluntarily returns later
-> same canonical actor and same persistent LifeTree
-> a new committed actor action is visible
-> a second evidence / structure / question chain grows
-> a second independent WorldEvent resolves
-> a second fruit reveals and persists
```

## Reuse boundary

The return does not add a second Dream runtime, world clock, database schema,
LifeTree identity or reveal engine. It reuses:

- `dream.encounters` with a new immutable `QuestionInstance`;
- the existing canonical actor `砚舟`;
- the existing `v60-life-tree-yanzhou-v1`;
- the existing two-AnswerSeal, WorldEvent, StoryFruit and Reveal path;
- the same ChartVersion, LifeCaseRevision and canonical structure fact.

Only authored content and semantic organ identities change.

## Authored return event

After the old channel result is reconciled, 砚舟 returns and loosens one
water-blocking stone on the already damp side. This committed action becomes
the baseline for the second question:

> 砚舟只松开湿侧的一块挡水石后，新细根会怎样改变？

The three choices compare the same two atoms: root spread and support
stability. Baseline evidence receives no outcome credit. The later evidence
is sealed independently before either viewer answer.

## Stable references

```text
Actor: v60-actor-yanzhou-v1

Committed return event: v60-world-event-yanzhou-stone-loosened-v1

```

The second organ set uses `v2` identities while remaining organs of the same
LifeTree aggregate.

## Runtime behavior

- A completed first encounter exposes one explicit return command.
- Continuing commits the return event, appends the actor timeline and
  activates the second organ set atomically.
- The current encounter is selected dynamically; first-visit constants are
  not used to settle, reveal or render the return.
- Refresh and process restart recover the same active encounter.
- Repeated world advance, reveal and reconciliation calls cannot move a
  completed encounter backward or duplicate Seal, Fruit or Reveal rows.
- No third encounter is authored; completion returns a bounded end state.

## Current visual boundary

The return intentionally uses the approved current LifeTree scene and stable
semantic anchors. New designer media can replace presentation assets through
the media registry without changing this state chain.
