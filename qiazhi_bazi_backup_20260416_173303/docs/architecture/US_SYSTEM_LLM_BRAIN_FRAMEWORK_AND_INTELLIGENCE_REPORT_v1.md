## 1. 三角色与「谁是大脑」

### 1.1 角色定义

| 角色 | 在架构中的含义 | 典型行为 |
|------|----------------|----------|
| **用户（裁决者）** | 输入生辰与时空锚点、勾选 Decision Inbox、确认/归档语义、触发重算与终审 | 提供意图与背书，不直接改物理内核代码 |
| **系统（大脑）** | 排盘、L0 物理推断、L1 交互、插件总线、L2 法典执行、元数据合并、编排终审请求、持久化裁决合并 | **持有真值管线与状态机**；决定何时、向模型喂什么、如何解析与落档 |
| **大模型（Auditor / Narrator）** | 在系统给定的边界与证据包内生成审计文案、终判 JSON+Markdown | **不替代**物理与法典计算；输出经解析、弱守卫与兜底策略处理 |

**结论**：当前产品的认知中枢在模型论上应表述为 **系统主导、LLM 外包自然语言与整合** 的架构，而不是「LLM 当大脑、系统只做 CRUD」。

### 1.2 三者如何互相沟通（逻辑信道）

以下为**信息关系**，不等于单次 HTTP 调用顺序：

```
用户 ──请求/勾选/意志──► 系统
系统 ──脱水证据+契约 Prompt──► 大模型
大模型 ──结构化输出/流式 token──► 系统
系统 ──合并后的 metadata / physics / 锚点层──► 用户（经前端）
用户 ◄──可读叙事与仪表盘── 系统（物理与 L2 结果主要由系统直接渲染，LLM 增强部分经系统转述）
```

- **用户 ↔ 系统**：API（analyze-seed、final-verdict、审计等）、持久化层合并、Inbox 状态。  
- **系统 ↔ 大模型**：系统组装 messages；模型返回文本；系统负责 JSON 提取、锚点解析、repair_mode、指纹注释。  
- **用户 ↔ 大模型**：无直连；用户所见 LLM 产出均为**系统托管下的二次呈现**。

更细的插件与终判链路见：`docs/engine/TRIPARTITE_PLUGIN_VERDICT_LLM_FLOW.md`。

## 2. 以「大脑 = 系统」为基础的框架结构（架构块）

从**系统内部**看，可拆为下列**固定顺序的智能化栈**（与实现强相关）：

1. **输入与配置融合**  
   生辰、大运流年、物理配置、`user_intention` 等对配置的补丁、用户决策注入等，在进物理引擎前由系统合并。

2. **L0 物理闭包**  
   确定性张量与元数据扩展；**不依赖 LLM**。

3. **插件与 L2 法典**  
   `on_physics_complete` 等钩子上：盲派、旺衰、格局法典（UniversalPatternEngine）、意志代理等；结果写入 `physics_tensor.meta` / `plugin_outputs`。

4. **语义与路由增强（仍属系统）**  
   因果路由、语义标签、结构预览、Inbox 管道等，把「可展示的中间态」准备好。

5. **LLM 调用点（系统决策「要不要叫模型」）**  
   物理审计、终审合成等：系统决定 tier、是否强制合成、如何清洗上下文。

6. **解析、持久化与防覆盖**  
   终判锚点层、`persistence_layer` 合并策略等，**系统保证资产不丢、不被空壳回包冲掉**。

与「骨 / 肉 / 魂」产品分层更细的表述见：`docs/architecture/INTELLIGENCE_LED_DECISION_FRAMEWORK_v2.md`（ILD）。

## 3. 智能性评估（定性报告）

本节给出**架构级**判断，供产品与技术路线讨论；**非**单一 benchmark 分数。

### 3.1 优势（系统作为大脑已体现出的「智能」）

| 维度 | 说明 |
|------|------|
| **真值与叙事分离清晰** | 物理与法典结论由确定性管线产生，LLM 主要承担翻译与整编，符合可控系统的设计方向。 |
| **模块化可演进** | 插件总线、法典 Manifest、意志代理等允许在不改叙事模型的情况下迭代「场」与「格」的规则。 |
| **用户意志有工程落点** | Inbox 勾选、持久化语义、参数侧车与 `user_intention` 对物理/L2 的渗透，使「裁决」不仅是聊天。 |
| **韧性设计** | 空响应、解析失败、弱模式断言锚点不合格时的回退路径，体现系统对模型不可靠性的预设。 |

### 3.2 局限（当前「智能性」的上限与风险）

| 维度 | 说明 |
|------|------|
| **无独立「逻辑真值校验层」** | 系统未在架构上保证：终审判词的吉凶取向与物理摘要符号一致；冲突时缺乏自动拒稿或强制异议块。 |
| **法典可解释性与叙事大脑未完全同构** | L2 引擎内部可有程序化轨迹，但若未稳定注入终审上下文，叙事层易「复读结论」而非「复述法典推理链」。 |
| **意志在语义层的显式性偏弱** | 意志多通过参数量与 L2 乘子改变结局；终审侧若缺少与 `intention_context` 对齐的强制叙事约束，用户感知上易出现「话里话外不像刚选了求财/避险」。 |
| **LLM 仍是单点语义风险** | 守卫多为格式与锚点类，而非命题与物理场的语义对撞。 |

### 3.3 综合判断（给裁决者的结论句）

- **系统智能（Engineering intelligence）**：**中高**——管线完整、真值来源明确、可插件化、有状态与持久化策略。  
- **叙事–物理闭环智能（Epistemic closure）**：**中偏低**——缺少显式校验层与法典–叙事同构通道时，「听起来对」与「场上真如此」仍可能脱节。  
- **整体定位**：符合 **「强系统、弱耦合 LLM」** 的工业型命理产品路线；若目标是 **「强自洽、可证伪的终局叙事」**，则需在系统侧增补 **验证与解释性管道**，而非单纯换大模型。
